# EdwinPAI Desktop — v0.2 Carryover Gaps

Features deferred from v0.1.1 to v0.2.

## P0 — Required for External Launch

### Runtime Bundle Pipeline
- Pre-built per-platform archives (Node.js + EdwinPAI dist + platform-specific deps)
- Desktop auto-downloads to `~/.edwinpai/runtime/`, extracts, starts gateway
- Target: ~200MB download, zero terminal required
- **Why P0**: Users cannot install EdwinPAI without Node.js/npm today

### Channel Write: WhatsApp QR Flow
- WhatsApp authenticates via QR code pairing with phone app
- Requires gateway-side streaming of QR codes back to Desktop
- Current: WhatsApp config exists but pairing must be done via CLI
- **Why P0**: WhatsApp is the most popular messaging platform

### Channel Write: Discord/Slack/Signal
- These wizards still use old Tauri IPC `create_channel_cmd` path
- Need to be migrated to config.patch (same as Telegram/Matrix)
- Lower priority than WhatsApp since Matrix/Telegram cover core demo

## P1 — Important for Product Quality

### 2FA Gate on App Launch
- YubiKey/TOTP/biometric before accessing the app
- BSV signing keys should be behind this gate
- Architecture designed but not implemented

### Device Sub-Key Signing
- Each messaging device gets BSV sub-identity derived from owner master key
- Signed message envelopes per channel
- Prevents message spoofing/injection

### Gateway-API Provider Management
- Currently: keys written via config.patch (merged into gateway config)
- Future: dedicated POST /v1/providers REST API for CRUD
- Better validation, audit logging, key rotation

### Memory/Shad Controls in Desktop UI
- Search/inspect memory index
- "Used memory for this reply" visibility (beyond citations)
- Re-index trigger, stats display

### Skills Management
- Browse/install/configure skills from Desktop
- Currently requires file system access

### Workspace Configuration
- Set workspace path, manage workspace files
- Currently configured via CLI

### Daemon Management
- Background service lifecycle (auto-start on boot, etc.)
- Currently requires systemd/launchd configuration

### Scheduled Tasks
- View/create/manage cron jobs from Desktop
- Currently requires gateway config or CLI

### Log Viewer
- View gateway logs from Desktop
- Filter by level, channel, session

### Session Management
- View/switch between chat sessions
- Session history, export

## P2 — Nice to Have

- Currently using `mode: 'ui'` to bypass origin check

- Then switch to `mode: 'webchat'` with proper auth

### Full Model Catalog
- Currently hardcoded list of common models

### Theme Customization
- Beyond light/dark toggle
- Custom accent colors, font sizes

### Per-Channel Configuration
- Room-level settings for Matrix
